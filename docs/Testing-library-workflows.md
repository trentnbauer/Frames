# Library workflow testing

Use a test library containing at least two different photos. Check the desktop UI in both light and dark themes. Mobile redesign is deferred to a separate pass. Originals should have the same contents before and after every action.

1. **Bulk edit:** select two photos in Library or a shoot → Edit details. Keep one camera filled and the other blank. Include camera and description, then preview. Fill blanks should preserve the filled camera. Turn off its per-field Fill blanks switch and preview again; the count should increase. Apply, then Undo. Test adding tags and location/date changes too. Edit a selected photo in another tab between preview and apply: applying must refuse newer changes. For more than 500 photos, reload during processing, then use Library → Bulk edit history → Resume. Undo must cover completed chunks together.
2. **Recovery:** remove a photo with ratings, tags and a description. It should disappear from Library, To do, review and old share access. Library → Recently removed & Undo → Restore should recover its metadata and ratings, rebuild its preview, and leave originals untouched. Share access must stay revoked. Disconnect a test original and restore another photo: it should report missing. Change the recovery period; decreasing it warns before expiring older snapshots. Old removals before this version have no recovery snapshot.
3. **Saved views:** filter Library by gear/tag/review state; Save current view. Switch away and select it again, rename it, change filters and Update filters. A newly imported matching photo should appear without editing the view. Delete the view; photos must remain.
4. **Schedule:** open Review schedule. Confirm Due now counts agree with review eligibility. Review selected now must use only that selection. Move one photo to a future local date; Upcoming should gain it and Due should lose it. Undo restores its previous date. Archived/missing photos belong under Excluded and cannot be rescheduled. Page controls should work for over 100 photos.
5. **Aliases:** own a camera called Minolta XD, with a photo naming MINOLTA XD-7. Gear → Gear name aliases → choose the owned camera → enter the metadata name → Preview → Save. Current and future photos should use Minolta XD while raw metadata and original EXIF remain unchanged. Rename the owned camera, remove/Undo the alias, and try a conflicting assignment. Blocklisting either name must clear the effective camera and automatic gear tags.
6. **Arrangements:** create a framed/cropped wall with a room photo. Arrangements → save A; change the wall/background and save B. Compare them and apply A: the current wall should be backed up, A restored, and existing live links pinned to their pre-apply wall. Share → Arrangement can deliberately pick A/B/live. Guest previews must show the chosen wall, with room backgrounds private. Download each print sheet. Done prevents Apply until reopened. Removing a photo from live candidates must not expose it to low-score cleanup if a saved version still references it.
7. **Imports:** upload a new image, a duplicate and an unsupported file. Open the per-file history from the completion screen; transfer and processing are separate batches. For failed processing, fix/reconnect the source and Retry: successful files must not be duplicated. Reload/restart between a pending import and retry. Removed photos must remain removed. Cloud provider transfer errors still use Cloud sync settings; use a test provider account for a live download/reconnect check.
8. **Wishlist:** add a wish with a URL, estimate and notes. Buy it with a different paid amount, then open Wishlist history → Bought. Estimate and paid amount should differ correctly. Edit purchase date/paid/notes. Changing current display currency must not relabel old amounts. Undo an unchanged purchase should restore the wish and remove owned gear. Edit/use owned gear first: Undo must refuse, while Restore wish preserves owned gear. Didn't buy should appear in its history tab and restore without creating owned gear. Home should show only active wishes.
9. **Isolation:** repeat with a second account. Saved views, recovery records, Undo, aliases, history and arrangements must stay private. A signed-out request to their APIs must require sign-in. Check stopped/expired/PIN-protected guest links retain their existing restrictions.

Automated coverage is in `server/src/libraryWorkflows.test.ts`, `server/src/multiuser.test.ts`, the existing metadata/gear/share/removal suites and the route input-fuzz suite. Browser verification uses isolated demo libraries; no production photos, live cloud accounts or outbound mail are required.
