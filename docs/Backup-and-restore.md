# Backup and restore

Everything Frames knows (reviews, tags, compositions, share links, settings) is in databases. Your originals are not part of them: back those up the way you already do.

- **The whole server** (administrators): Settings, Backup, **Download a server backup**. One archive with the people (accounts, roles, folders) and every person's library database. The server's own settings (sign-in providers, the tunnel, shared AIs, keys) are **not** in it, since they belong in the env file, and sign-in sessions and each person's keys are taken out too. A copy of this archive is also written once a day (the last seven kept) to the backups folder (`BACKUP_DIR`, the `/backups` mount in the compose files). Configured off-server copies are described under [Off-server backups](Off-server-backups), or copy the backup folder using your own tooling.
- **Your own data** (everyone): Settings, Your data, **Download my backup**, the same thing for just your library.
- **Automatic backups**: one a day for each library, the last seven kept, in that library's `backups` folder. Settings, Backup lists them.
- **Restore** (administrators, Settings, Backup): **Restore from a file…** takes a server backup you downloaded, or pick one of the daily archives in the backups folder. It is checked first (every database must be sound and the people database must be there; nothing is applied if not) and put aside, and **applied the next time Frames starts**: **Restart Frames now** does that for you when the container has a restart policy (the compose files do), or restart it yourself. Everyone is signed out and signs in again. The databases it replaces are kept in `backups/before-restore-<time>` in the data folder, and the photographs are not touched. A restore brings back people and libraries only: the **server's own settings** (sign-in providers, the tunnel, shared AIs, keys, the privacy page) are **not in backups** and are **kept as they are** on the server doing the restore, so on a new server you set them up first, or start it with your env file (Settings, Env file). Each library's own daily copy (`auto-…db`) can still be restored by hand: stop Frames, replace that library's `frames.db` (`users/<number>/frames.db` for everyone but the first administrator), delete any `-wal` and `-shm` files beside it, and start it again, then Settings, Your data, **Rebuild all** if previews are missing. A restored copy has no keys or sign-in sessions: enter the keys again and sign in.
- On start-up Frames checks the database and logs a clear message if it is damaged.

To send the daily archive to S3, Dropbox, Google Drive or OneDrive, see [Off-server backups](Off-server-backups).

## Authenticator state

Portable backups exclude private authenticator state, recovery-code records and verified sessions. On the same server, a restore retains current authenticator state and unused recovery codes only for matching live identities; it does not resurrect used recovery codes or attach a secret to a different account with a reused ID. Users restored onto another server need to enrol again under its policy. Emergency recovery and verified administrator resets are described under [Signing in](Sign-in).
